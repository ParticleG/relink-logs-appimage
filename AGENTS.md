# Repository Guidelines

## Project Overview

`relink-logs-appimage` is an unofficial Arch Linux AUR recipe for the official
x86_64 AppImage releases of
[`villith/relink-logs`](https://github.com/villith/relink-logs). This repository
contains packaging and release automation only; the Relink Logs application,
hook, and runtime internals live upstream. The package installs the unmodified
AppImage as the `gbfr-logs` command.

Keep the credits and independence statements in `README.md`: Relink Logs is an
independent continuation of `false-spring/gbfr-logs`, whose original work was
based on `nyaoouo/GBFR-ACT` reverse engineering.

## Architecture & Data Flow

1. `PKGBUILD` declares the exact upstream release tag, AppImage, license,
   checksums, dependencies, and install layout.
2. `makepkg` downloads both sources. `prepare()` runs the AppImage with
   `--appimage-extract` only to obtain desktop and icon resources.
3. `package()` installs the original AppImage under `/opt`, creates the
   `/usr/bin/gbfr-logs` symlink, and installs XDG resources and the MIT license.
4. `.SRCINFO` is generated from `PKGBUILD` and exposes the recipe to the AUR.
5. `.github/workflows/aur-publish.yml` discovers the latest stable release,
   updates version/tag/checksums, builds in an isolated Arch container, commits
   recipe changes, and publishes to the AUR.

There is no application-layer state management, dependency injection, async
runtime, service layer, or source-module graph in this repository.

## Key Directories

- `.github/workflows/` — the single CI/CD workflow for release discovery,
  package verification, GitHub updates, and AUR publishing.
- `src/` — generated by `makepkg`; ignored and never a version-controlled source
  directory.
- `pkg/` — generated package staging tree; ignored and safe to recreate.
- Project root — all maintained package metadata and documentation. There are no
  permanent `src/`, `tests/`, `scripts/`, or `docs/` trees.

## Development Commands

Run packaging commands from the repository root on Arch Linux:

```bash
# Download sources and verify both fixed SHA-256 checksums
makepkg --verifysource

# Clean build, install missing dependencies, and install the package
makepkg -Csi

# Regenerate AUR metadata after any recipe metadata change
makepkg --printsrcinfo > .SRCINFO

# Show the package archive path without building
makepkg --packagelist
```

After a build, reproduce the explicit desktop checks used by CI:

```bash
desktop-file-validate \
  pkg/relink-logs-appimage/usr/share/applications/gbfr-logs.desktop
test -L pkg/relink-logs-appimage/usr/bin/gbfr-logs
test -f \
  pkg/relink-logs-appimage/usr/share/icons/hicolor/256x256@2/apps/gbfr-logs.png
```

Maintainer workflow commands:

```bash
gh workflow run aur-publish.yml -f force_publish=true
gh api repos/villith/relink-logs/releases/latest
```

## Code Conventions & Common Patterns

- Treat `PKGBUILD` as Bash: quote all paths, use arrays for Arch metadata, use a
  leading underscore for derived variables, and split long commands with `\`.
- Keep source and checksum arrays positional. Exactly two SHA-256 entries are
  expected, in AppImage-then-license order; never replace them with `SKIP`.
- Preserve upstream names for desktop integration (`gbfr-logs`) and the package
  name for owned directories (`relink-logs-appimage`).
- Install executables with `install -Dm755` and metadata/icons/licenses with
  `install -Dm644`.
- Keep the AppImage in `noextract`. `prepare()` must remove stale
  `squashfs-root` before extracting a new release.
- Preserve `options=('!strip' '!debug')`; the upstream AppImage must not be
  stripped or split into debug content.
- A new upstream version resets `pkgrel` to `1`; packaging-only changes increment
  `pkgrel`. `_tag` must preserve whether upstream used a `v` prefix.
- Workflow shell blocks use `set -euo pipefail`; inline Python validates field
  counts and fails closed instead of guessing.
- Keep documentation in concise English Markdown. Update `README.md` when user
  commands, paths, dependencies, automation, or upstream relationships change.

## Important Files

- `PKGBUILD` — source of truth for package metadata, checksums, extraction, and
  install layout.
- `.SRCINFO` — generated AUR metadata. Regenerate it; do not edit it as an
  independent source of truth.
- `.github/workflows/aur-publish.yml` — scheduled/event-driven update, isolated
  validation, GitHub commit, and AUR deployment pipeline.
- `README.md` — installation, runtime limitations, automation summary, license,
  and required upstream credits; it is also copied to the AUR repository.
- `.gitignore` — excludes `makepkg` directories, downloaded AppImages/licenses,
  and package archives; it is also copied to the AUR repository.

The installed layout is part of the contract:

```text
/opt/relink-logs-appimage/gbfr-logs.AppImage
/usr/bin/gbfr-logs
/usr/share/applications/gbfr-logs.desktop
/usr/share/icons/hicolor/{32x32,128x128,256x256@2}/apps/gbfr-logs.png
/usr/share/licenses/relink-logs-appimage/LICENSE
```

## Runtime/Tooling Preferences

- Package builds require Arch Linux tooling: Bash, `makepkg`, `pacman`, and
  `base-devel`. Do not substitute npm, Node.js, Bun, or another package manager.
- Runtime dependencies are `fuse2` and `hicolor-icon-theme`; CI additionally
  installs `desktop-file-utils` for validation.
- GitHub orchestration runs on `ubuntu-latest` and expects `gh`, `jq`, Python 3,
  GNU `sha256sum`, Git, and Docker. Actual package work runs in
  `archlinux:base-devel` containers.
- The workflow requires the `AUR_SSH_PRIVATE_KEY` secret. Keep checkout
  credentials non-persistent and expose `github.token` only to steps that need
  it.
- The downloaded AppImage is executed during extraction. Keep it inside the
  temporary build mount with no `.git`, GitHub token, AUR key, workspace mount,
  or Docker socket.
- Continue pinning third-party actions to immutable commit SHAs. Do not add
  untrusted pull-request triggers to a workflow that can reach publishing
  credentials.

## Testing & QA

There is no unit, integration, E2E, GUI, or coverage framework. QA covers the
packaging contract, not upstream application behavior.

The CI workflow verifies:

- supported release tag shape and the exact expected amd64 AppImage asset;
- two downloaded source checksums and exactly two recipe checksum entries;
- `makepkg --verifysource --force --noconfirm`;
- a complete `makepkg --force --noconfirm` build as a non-root user;
- regenerated `.SRCINFO`;
- desktop entry syntax;
- the launcher symlink and `256x256@2` icon path.

For every packaging change, at minimum verify sources, perform a clean build,
regenerate `.SRCINFO`, and repeat the desktop/symlink/icon assertions above.
Changes to the workflow should also pass `actionlint`. Do not claim application
runtime coverage unless the packaged AppImage was separately launched and the
observed scenario is stated.
